# Паспорт объекта — извлечение из Word

## Установка

    pip install -r requirements-dev.txt

Эта команда уже ставит всё нужное для распознавания текста с картинок —
отдельных программ или прав администратора не требуется.

## Запуск

    python run.py

Откройте http://127.0.0.1:5000 в браузере.

### Распознавание текста с картинок и сканов

Часть данных в документах приходит картинкой, а не текстом: таблица
показателей в ТЗ, отсканированный протокол условий. Программа умеет их
читать, и делает это **сама, без настроек** — при условии, что в Windows
установлен русский язык распознавания (обычно он уже есть). Проверить можно
так:

    python -c "from app import win_ocr; print(win_ocr.available())"

Если печатает `True` — всё работает. Распознавание идёт на вашем компьютере:
никуда ничего не отправляется, интернет не нужен, платить не за что. Быстро:
все 26 картинок технического задания читаются меньше чем за 2 секунды,
страница протокола формата A3 — примерно за секунду.

Если печатает `False` (нет русского языкового пакета или программа работает
не под Windows), включается запасной распознаватель `easyocr`. Он работает
везде, но на обычном процессоре тратит **минуты** на одну картинку, поэтому
включается только вручную:

    # PowerShell
    $env:OCR_FALLBACK_ENABLED="1"; python run.py

    # cmd
    set OCR_FALLBACK_ENABLED=1 && python run.py

При первом запуске с ним один раз скачиваются файлы модели — на это нужен
интернет разово. Если скачать не удалось, программа продолжает работать,
просто поля с картинок остаются пустыми и их можно заполнить вручную.

### Отдельно про протокол окончательных условий

Если протокол — скан, программа сначала пробует прочитать его через Claude
(пара секунд, нужен ключ и деньги на счёте). Не вышло — не задан ключ,
кончились средства, нет сети — тут же читает сама, распознаванием Windows.
Разрешения спрашивать не у чего: быстрый путь уже отпал, и выбор не между
«быстро» и «медленно», а между «прочитать» и «не прочитать».

Если ни один способ ничего не разобрал, программа честно скажет об этом и
предложит вписать четыре значения вручную — их немного.

## Выгрузка сравнения в Excel

Откройте «Сравнить объекты» в левом меню, отметьте нужные проекты галочками
и нажмите «Выгрузить в Excel» —
скачается файл в том виде, в каком сравнение стоимости обычно ведут на бумаге:
один лист, проекты идут колонками. У каждого проекта сверху название, под ним
фото объекта, дальше год подписания, класс, генподрядчик, площади и ставка НДС,
а ниже — таблица стоимости по видам работ.

Та же кнопка есть и на самой странице сравнения, рядом с «Сохранить в PDF».

Файл рассчитан на то, чтобы с ним работали дальше:

- Стоимость по видам работ берётся из сметы, если она загружена в проект.
  Программа читает разделы верхнего уровня («№ раздела» = 1, 2, 3…) и
  раскладывает их по строкам отчёта по названию раздела, а не по номеру:
  нумерация в каждой смете своя, а названия работ — общепринятые. Если сметы
  нет, строки остаются пустыми и заполняются вручную, а итоговая строка
  показывает цену работ по договору.
- У каждой заполненной строки затрат есть примечание (красный уголок ячейки,
  видно при наведении) — из каких разделов сметы сложилось число. Так видно,
  что куда попало, и не нужно открывать смету, чтобы это проверить.
- Раздел, для которого в отчёте нет строки, в отчёт не попадёт — но и не
  потеряется молча: его название пишется в журнал программы.
- Все ₽/м² и итоги пересчитываются сами: впишите суммы или поправьте общую
  площадь — колонка пересчитается.
- Рядом с ценой за м² каждого проекта красным показано, насколько он дороже или
  дешевле первого выбранного.
- Жёлтым подсвечено то, что программа не смогла найти в документах, — эти
  ячейки нужно заполнить самому. Нулями они не заполняются, чтобы пустое
  значение нельзя было принять за настоящий ноль.

Ставка НДС ставится по году подписания договора: 20% по 2025 год включительно,
22% начиная с 2026-го.

## Тесты

    pytest

Тесты, использующие реальные примеры документов (папка `tests/fixtures/`),
пропускаются, если файлы туда не скопированы. Тест на реальное
распознавание текста (`tests/test_ocr.py`) пропускается, если EasyOCR не
смог инициализироваться (например, нет сети для первой загрузки модели).
Чтобы прогнать всё:

1. Скопируйте `250204 ДГП_Пр_Мира.docx` → `tests/fixtures/dgp_mira.docx`
2. Скопируйте `Прил. 1. Техническое задание Проспект Мира.docx` →
   `tests/fixtures/tz_mira.docx`
3. Убедитесь, что зависимости установлены (см. "Установка")
4. Запустите `pytest -v`

## Ручная сквозная проверка

1. `python run.py`
2. Откройте http://127.0.0.1:5000, нажмите "Создать проект"
3. Введите название "Проспект Мира", загрузите те же 2 файла из шага выше
4. После создания должна открыться страница проекта: Генподрядчик = "ООО «АНТТЕК»"
   заполнен автоматически (зелёный значок)
5. Без `OCR_FALLBACK_ENABLED=1` поля площади (подземная/надземная/общая)
   останутся пустыми — это ожидаемо, впишите значения вручную. Если запустили
   с включённым OCR — эти поля должны заполниться значениями, распознанными
   с картинки на листе 5 ТЗ (67 413 / 13 297 / 54 116 м², порядок полей может
   отличаться), с синим значком "С картинки — проверьте", но на обычном
   процессоре это может занять несколько минут.
6. Год подписания и класс здания — пустые, подсвечены жёлтым, доступны для
   ручного ввода
7. Впишите значения в пустые поля, нажмите "Сохранить" — после перезагрузки
   страницы введённые значения должны сохраниться, а с полей, заполненных
   через OCR, значок "проверьте" должен исчезнуть, если вы изменили значение
