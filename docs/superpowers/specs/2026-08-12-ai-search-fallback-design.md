# Поиск полей паспорта через Claude API с деперсонализацией

## Контекст

Сейчас поля паспорта объекта (генподрядчик, цена работ, год подписания,
класс здания, площади) ищутся в тексте ДГП/ТЗ через регулярки
(`app/extractors.py`), с опциональным резервом через OCR картинок
(`OCR_FALLBACK_ENABLED`, `app/passport.py::_apply_ocr_fallback`).
Регулярки не находят значения на нестандартных формулировках.

Референс: репозиторий `zhukovvlad/kpi-tenders-python` — Python-воркер
для тендерной документации, в котором есть модуль `anonymize`:
деперсонализация текста через NER-библиотеку **Natasha** (находит
организации, персоны, ИНН, заменяет на токены `<ORGANIZATION_1>`,
`<PERSON_1>`, `<INN_1>`) перед отправкой в LLM (Gemini). Мы применяем
тот же приём деперсонализации, но перед вызовом Claude API как ещё
одного резервного способа поиска полей.

## Общий поток

1. Обычный поиск по regex (как сейчас, без изменений).
2. Если `OCR_FALLBACK_ENABLED=1` и есть недостающие поля — резерв через
   OCR (как сейчас, без изменений).
3. Если после шагов 1–2 остались недостающие поля — резерв через
   Claude API:
   1. Собрать текст ДГП и ТЗ (абзацы + таблицы, плюс распознанный OCR-текст,
      если он был получен на шаге 2) в один текстовый контекст.
   2. Деперсонализировать контекст (см. ниже) — получить анонимизированный
      текст и словарь `токен → оригинал`.
   3. Запросить у Claude только недостающие поля со структурированным
      ответом (JSON-схема).
   4. Для каждого возвращённого значения: если оно совпадает с токеном
      из словаря — заменить на оригинал.
   5. Числовые поля прогнать через `extractors.parse_number`, как и
      в остальных резервах.
4. Шаг 3 выполняется всегда (без переменной окружения-переключателя),
   но только когда есть недостающие поля — если regex/OCR нашли всё,
   Claude не вызывается.

## Деперсонализация (`app/anonymize.py`)

Новый модуль. Через библиотеку **Natasha** (`Segmenter`, `NewsEmbedding`,
`NewsNERTagger`) находим сущности `PER` и `ORG` в тексте. Дополнительно
регуляркой находим ИНН (10 или 12 цифр рядом со словом «ИНН»).

Функция `anonymize_text(text: str) -> tuple[str, dict[str, str]]`:
- каждое уникальное найденное упоминание организации получает токен
  `<ORGANIZATION_N>`, персоны — `<PERSON_N>`, ИНН — `<INN_N>`
  (нумерация сквозная в порядке первого упоминания);
- в тексте все упоминания заменяются на токены;
- возвращается анонимизированный текст и словарь `токен → оригинальная
  подстрока` для обратной подстановки.

Функция `deanonymize_value(value, token_map) -> value` — если строковое
значение целиком совпадает с каким-то токеном, вернуть оригинал из
словаря, иначе вернуть как есть без изменений.

## Запрос к Claude (`app/ai_extractor.py`)

Новый модуль.

- `build_context_text(dgp, tz) -> str` — плоский текст: абзацы и строки
  таблиц ДГП и ТЗ (в существующем формате `DocxContent`), через перевод
  строки.
- `extract_missing_fields(missing_fields: list[str], context_text: str) -> dict`:
  1. `anonymized_text, token_map = anonymize_text(context_text)`.
  2. Вызов `client.messages.create(model="claude-opus-5", ...)` с
     `output_config.format` — JSON-схема, где ключи — это ровно
     `missing_fields`, значения — строка или `null` (без выдумывания
     значений, если поля в тексте нет).
  3. Разобрать JSON-ответ, для каждого значения — `deanonymize_value`.
  4. Для полей из `NUMERIC_FIELDS` — прогнать через `parse_number`.
  5. Вернуть словарь `{field: value}` только для полей, которые
     удалось найти (не `null`).

Ключ берётся из окружения (`ANTHROPIC_API_KEY`) — как принято для
интеграций с Claude API, никакой отдельной переменной под это не
заводим.

## Обработка ошибок

Любая ошибка на шаге Claude (нет ключа, нет сети, таймаут, ошибка API,
Natasha не смогла загрузить модель) — резерв просто не срабатывает для
затронутых полей, создание проекта не прерывается. Аналогично тому, как
сейчас ведёт себя OCR-резерв при неудачной загрузке модели.

## Интеграция в `app/passport.py`

`build_passport`: после `_apply_ocr_fallback` — если есть поля, всё ещё
равные `None` (кроме `project_name`), вызвать
`ai_extractor.extract_missing_fields`, слить найденные значения в `data`,
добавить их имена в новый список `data["ai_fields"]` (по аналогии с
`ocr_fields`).

## Интерфейс

Поля, заполненные через Claude, помечаются отдельным значком, отличным
от OCR-значка — например, «Найдено через AI — проверьте» (другой цвет
бейджа). Как и `ocr_fields`, при ручном изменении значения поле
перестаёт быть особым (убирается из `ai_fields`) — логика та же, что
уже есть для `ocr_fields` в `app/routes.py::update_project`.

## Зависимости

В `requirements.txt` добавить:
- `anthropic` — официальный SDK Claude API.
- `natasha` — NER для русского языка.

## Тесты

- `app/anonymize.py`: юнит-тесты на распознавание организации/персоны/ИНН
  в тексте и корректность обратной подстановки.
- `app/ai_extractor.py`: тест с замоканным клиентом Claude API —
  проверить, что в модель уходит анонимизированный текст (без реальных
  названий/ИНН), и что в результате токены заменены на оригиналы.
- `app/passport.py`: тест, что `ai_fields` заполняется только для полей,
  которых не нашли regex и OCR, и что ошибка вызова Claude не прерывает
  `build_passport`.

## Вне рамок задачи

- Настройка деперсонализации (нельзя отключить) — сделано осознанно,
  не настраиваемо.
- Отдельная переменная окружения для включения/отключения самого
  резерва через Claude — не делаем, шаг всегда доступен, но срабатывает
  только при недостающих полях.
