# Резервное распознавание полей с картинок в .docx — дизайн

Дата: 2026-08-10

## Цель

В MVP (см. [2026-08-07-object-passport-extraction-design.md](2026-08-07-object-passport-extraction-design.md))
6 полей паспорта объекта извлекаются из текста и таблиц .docx-файлов. На
реальном примере обнаружилось: часть значений (три площади из ТЭП) в
исходном ТЗ вставлена не как текст/таблица, а как картинка (скриншот таблицы
на листе 5) — такой текст `document_reader.py` физически не видит, поэтому
поля остаются пустыми, хотя данные в документе фактически есть.

Эта задача добавляет **резервный шаг**: если после обычного разбора поле всё
ещё не найдено, программа находит картинки, вставленные в загруженные файлы,
распознаёт на них текст (OCR) и повторяет тот же поиск уже по распознанному
тексту. Если и так нашлось — значение подставляется автоматически, но
помечается в интерфейсе отдельным значком, отличным от обычного
автозаполнения, — как требующее проверки человеком.

## Мотивация / входные данные

Реальный пример (лист 5 ТЗ, вставлен как картинка, распознан пользователем
визуально):
```
Общая площадь                          м2   67 413
Общая площадь подземного паркинга      м2   13 297
Общая наземная площадь                 м2   54 116
```

Два важных наблюдения по этому примеру:
1. Документ использует слово **"наземная"**, а не "надземная". Текущий
   `extract_aboveground_area` ищет только токен `надземн` — с этим примером
   он не сработал бы даже если бы текст был обычным, не картинкой.
2. Строка "Общая площадь" (итог) и "Общая площадь подземного паркинга"
   обе содержат токены `обща` + `площад`, которые сейчас используются как
   единственный критерий для `extract_total_area`. На такой формулировке
   есть риск случайно принять площадь паркинга за общую площадь.

Обе проблемы исправляются в рамках этой задачи и работают в обоих режимах
(обычный текст/таблицы и распознанный с картинки текст), так как использует
общую логику.

## Ограничения (продолжают действовать из MVP, ничего не меняется)

- Никаких внешних облачных LLM/API. Распознавание текста с картинок —
  локальная библиотека Python (EasyOCR), устанавливается через `pip`, без
  прав администратора, никакой отдельной программы на компьютер не ставится.
  При первом запуске один раз скачивает файлы модели (десятки-сотни МБ) —
  дальше работает полностью без интернета.
- Заполнение полей — автоматическое, без запроса подтверждения. Разница
  только в том, что поле, заполненное с картинки, помечается отдельно как
  требующее проверки — но подставляется в форму сразу, не ждёт клика.
- Никакой ML-модели/интеллектуального сопоставления — те же самые правила
  (регулярные выражения, поиск ключевых слов), что и для обычного текста,
  просто применённые к дополнительному источнику текста.
- Если распознавание недоступно (программа не установлена, картинка
  повреждена, неподходящий формат) — это не ошибка уровня всего запроса,
  поле просто остаётся `null`, как и раньше.

## Архитектура

```
document_reader.py
   читает .docx → DocxContent(paragraphs, tables, images)
                                                 │
                                                 ▼
                                            app/ocr.py
                                      recognize_text(images) -> [строки]
                                                 │
                                                 ▼
                                        extractors.py (те же правила)
                                                 │
                                                 ▼
                                  passport.py: build_passport()
                                  — сначала обычный разбор,
                                  — для оставшихся None полей — резерв через OCR
                                  — passport["ocr_fields"] = [список полей из OCR]
```

## Компоненты

### `document_reader.py` — добавляется `images`

`DocxContent` получает третье поле: `images: list[bytes]` — необработанные
байты каждой картинки, найденной в архиве .docx под `word/media/` (только
растровые форматы — png/jpg/jpeg/bmp/gif/tiff; векторные форматы `.emf`/`.wmf`,
которые Word иногда использует для диаграмм, пропускаются — OCR по ним не
работает без дополнительной конвертации, и в изученных примерах таких файлов
нет).

`read_docx()` не расшифровывает и не проверяет содержимое картинок — это не
его ответственность, только достаёт байты по структуре архива, как и для
текста/таблиц.

### `app/ocr.py` — новый модуль, единственная точка входа в распознавание

```python
def recognize_text(images: list[bytes]) -> list[str]:
    """Распознаёт текст на каждой картинке. Никогда не бросает исключений —
    картинка, которую не удалось прочитать (битый файл, неподдерживаемый
    формат, сбой при первой загрузке модели), просто не даёт текста."""
```

Внутри — библиотека `EasyOCR` (`pip install easyocr`, без Tesseract и без
прав администратора). Она распознаёт не целые строки, а отдельные фразы со
своими координатами на картинке — модуль сам собирает их в строки по
вертикальному положению (что примерно на одной высоте — одна строка,
дальше слева направо), чтобы остальной код мог работать с обычным списком
строк текста, как и раньше. Любая ошибка на этом шаге перехватывается
конкретно для этой картинки — остальные картинки обрабатываются дальше.

Это единственное место в проекте, которое знает про EasyOCR — если
понадобится когда-то заменить способ распознавания, менять нужно только
этот файл.

### `extractors.py` — две точечные правки + одна новая функция

1. Токены для площади надземной части расширяются: `надземн` **или**
   `наземн` (оба варианта считаются одним и тем же полем).
2. `extract_total_area` (и его резервный аналог для текста, см. ниже)
   получает исключающее условие: строка/ячейка считается "общей площадью"
   только если содержит `обща`+`площад` **и не содержит** `подземн`,
   `надземн` или `наземн` — иначе это площадь конкретной части, не итог.
3. Новая функция `_find_area_value_in_text(lines, must_contain, must_not_contain)`
   — аналог уже существующей `_find_area_value`, но для плоского списка строк
   (как возвращает OCR) вместо таблицы: ищет строку, где есть все токены из
   `must_contain` и нет токенов из `must_not_contain`, извлекает число после
   найденной метки в этой же строке (либо в следующей, если в этой строке
   после метки числа нет) — тем же безопасным способом, что уже используется
   для ячеек таблиц (число парсится без "прилипания" единицы измерения,
   опыт с "50 000 м2" уже учтён).

Остальные извлекающие функции (`extract_general_contractor`,
`extract_signing_year`, `extract_building_class`) не меняются: они уже
работают со списком строк (`paragraphs`), поэтому резервный проход просто
подсовывает им распознанный с картинок текст вместо обычных абзацев — им не
нужно знать, что текст пришёл с картинки.

### `passport.py` — резервный проход + отметка источника

`build_passport()`:
1. Считает все 6 полей как сейчас (без изменений в этой части).
2. Если хотя бы одно поле осталось `None` — только тогда распознаёт картинки
   соответствующего файла (лениво, чтобы не тратить время, когда всё уже
   нашлось в тексте):
   - для `general_contractor`, `year_signed` — картинки из ДГП;
   - для `building_class` — картинки из ДГП и ТЗ;
   - для трёх полей площади — картинки из ТЗ.
3. Для каждого поля, оставшегося `None` после обычного разбора, повторяет
   тот же поиск на распознанном тексте. Найденные так поля добавляются в
   список `ocr_fields` в итоговом словаре.

```json
{
  "project_name": "Проспект Мира",
  "year_signed": null,
  "building_class": null,
  "general_contractor": "ООО «АНТТЕК»",
  "underground_area_sqm": 13297.0,
  "aboveground_area_sqm": 54116.0,
  "total_area_sqm": 67413.0,
  "ocr_fields": ["underground_area_sqm", "aboveground_area_sqm", "total_area_sqm"]
}
```

`ocr_fields` — новый необязательный ключ, старые `passport.json` без него
продолжают работать (в коде читается как `passport.get("ocr_fields", [])`).

### Веб-интерфейс

- `project.html`: у поля, входящего в `ocr_fields`, — отдельный значок
  ("Распознано с картинки — проверьте"), отличный от зелёного "Заполнено
  автоматически" и жёлтого "Заполните вручную".
- `update_project` (сохранение ручной правки): если пользователь изменил
  значение поля, входящего в `ocr_fields`, на другое — поле убирается из
  `ocr_fields` (пользователь его проверил и подтвердил/исправил). Если
  значение оставлено как было — отметка сохраняется.

## Обработка ошибок

- Библиотека распознавания не смогла загрузиться (например, нет интернета
  для первой, разовой загрузки модели) / картинка не читается — `app/ocr.py`
  перехватывает это для конкретной картинки, остальная обработка идёт как
  обычно, поле в худшем случае остаётся `null`, как и без этой функции.
- Загрузка/создание проекта никогда не должна падать из-за OCR — эта
  часть работы обёрнута так, что её сбой эквивалентен "картинок с текстом не
  нашлось".

## Тестирование

- `app/ocr.py`: тест на синтетической картинке с чётким крупным текстом
  (сгенерированной в тесте через Pillow) — распознанный текст должен
  содержать ожидаемую подстроку. Если библиотека распознавания не смогла
  инициализироваться в среде, где идёт тест (например нет сети для первой
  загрузки модели) — тест аккуратно пропускается (`pytest.skip`), как уже
  сделано для тестов на реальных файлах-примерах. Отдельно — юнит-тест на
  сборку отдельных распознанных фраз в строки по координатам, без
  обращения к самой модели распознавания.
- `document_reader.py`: синтетический .docx с встроенной картинкой — байты
  должны совпасть с исходными.
- `extractors.py`: `_find_area_value_in_text` — юнит-тесты без всякого OCR,
  на обычных строках текста: находит число сразу после метки, находит число
  на следующей строке, не путает "общую площадь" со "площадью подземного
  паркинга", распознаёт "наземная" как надземную площадь.
- Сквозной тест на реальном примере (`tests/fixtures/tz_mira.docx`, где
  картинка с площадями на самом деле есть) — после реализации нужно вручную
  проверить, что три поля площади заполняются и попадают в `ocr_fields`;
  если распознавание даст неточный результат из-за качества картинки —
  задокументировать как известное ограничение, а не подгонять код под
  конкретные цифры.

## Установка (README)

Добавить шаг: `pip install -r requirements-dev.txt` теперь дополнительно
ставит `easyocr` — отдельно ничего устанавливать не нужно, прав
администратора не требуется. При первом использовании (первая загрузка
проекта с картинкой, где что-то не нашлось в тексте) один раз скачиваются
файлы модели распознавания — на это нужен интернет разово, дальше не
требуется. Если по какой-то причине это не сработает, резервный шаг просто
не найдёт ничего дополнительного, остальное приложение продолжит
работать как раньше.

## Вне рамок этой задачи

- Точное определение, на какой странице/в каком месте документа находится
  нужная картинка — распознаются все картинки файла подряд.
- Ускорение/распараллеливание OCR, ограничение количества картинок — при
  текущих объёмах (несколько проектов, документы на десятки картинок)
  не требуется.
- Показ пользователю самой картинки или распознанного текста целиком —
  только итоговое значение поля.
