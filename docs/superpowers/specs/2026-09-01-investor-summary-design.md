# Сводка для инвесторов: смета, прогноз и подписанное удорожание по всем объектам

## Цель

Отдельная страница, где по каждому загруженному объекту в одной строке
видно: смета, прогнозируемое удорожание (реестр претензий ВИС) и
подписанное удорожание (файл «удорожания» объекта) — и дельта между
прогнозом и тем, что уже подписано. Это то, что команда показывает
инвесторам: не «сколько стоит объект», а «сколько риска по нему ещё не
закрыто подписью».

Внутренний отчёт — открыт всем, у кого есть доступ к приложению сейчас,
без отдельной авторизации. Инвесторы видят его с экрана или в выгрузке,
которую делает команда, а не заходят в приложение сами.

## Что уже есть и берётся как основа

- `app/routes.py: _section_costs` / `_estimate_totals` — сумма сметы
  проекта по разделам (`excel_report.estimate_costs`). Смета в этой
  сводке — просто `sum(...values())` того же словаря.
- `app/routes.py: _cost_increase_report` → `app/cost_increase.py` —
  файл «удорожания» проекта, уже прочитанный и сверенный со сметой.
  `report.total.delta` — «стало минус смета» по всей выборке видов
  работ, `report.from_estimate` — правда ли у дельты вообще есть смета
  в качестве базы (иначе файл сравнивает сам себя с «было», и это не
  та же по смыслу цифра).
- `app/routes.py: _vis_price_increase_rows` → `app/vis_reestr.py` —
  реестр претензий ВИС целиком, разобранный один раз на всю страницу
  (не на объект).
- `app/comparison.py: vis_overrun_by_slug` — сопоставление объекта
  реестру по названию (пересечение слов в обе стороны) и его
  прогнозируемое удорожание, уже используется на странице сравнения.
- `templates/predicted_overrun.html`, `templates/compare_vs_average.html`
  — образец для новой страницы: `page-head` + `card sections-card` +
  `sections-table`.

Ничего из перечисленного не переделывается — сводка только сводит уже
посчитанные в другом месте цифры в одну таблицу.

## Расчёт (новый модуль `app/investor_summary.py`)

Модуль без Flask и без чтения файлов — только сборка уже прочитанных
данных в строки таблицы, как `comparison.py` собирает свои. Один вход
на строку:

    build_table(slugs, project_names, estimate_totals_by_slug,
                cost_increase_reports_by_slug, vis_overrun_by_slug)

Для каждого `slug`:

- **Смета** = `sum(estimate_totals_by_slug[slug].values())`, или
  `None`, если словарь пуст (сметы нет / не разобралась).
- **Прогнозируемое удорожание** = `vis_overrun_by_slug.get(slug)` —
  `None`, если реестр не сопоставил объект ни с одной строкой.
- **Подписанное удорожание** — `None`, если файла «удорожания» нет
  (`cost_increase_reports_by_slug.get(slug)` пуст) **или** у него
  `from_estimate` ложно (дельта посчитана против «было», а не против
  сметы — несопоставимо с остальными объектами). Иначе —
  `report.total.delta`.
- **Дельта** = Прогнозируемое − Подписанное, только если обе величины
  известны. Положительная — по объекту ещё есть неподписанный риск,
  спрогнозированный реестром сверх того, что уже согласовано.
  Отрицательная — подписано больше, чем сейчас показывает прогноз
  (реестр обновился, или расхождение стоит проверить руками) — цифра
  не прячется и не подрезается до нуля, показывается как есть, только
  подсвечивается other-цветом.

Строки сортируются по названию проекта (`project_names[slug]`) —
предсказуемый порядок по умолчанию, дальше сортировка кликом по
заголовку, как на странице сравнения.

Итоговая строка: сумма по каждой колонке среди объектов, где значение
известно, плюс счётчик «N из всего объектов» под каждой суммой — тот
же приём, что уже используется в средних показателях сравнения
объектов (`per_sqm_count из count`). Пустая сумма (ни у одного объекта
нет значения) — прочерк, не ноль.

## Сбор данных (новый маршрут `app/routes.py: investor_summary`)

    GET /investors  →  main.investor_summary

- `slugs = storage.list_project_slugs(root)` — все объекты, не только
  выбранные, в отличие от `/compare`.
- Паспорта — `_safe_passport` на каждый slug (не должен ронять
  страницу, как и везде).
- `estimate_totals_by_slug[slug] = _estimate_totals(root, slug)`.
- `cost_increase_reports_by_slug[slug] = _cost_increase_report(root, slug)`.
- `vis_rows = _vis_price_increase_rows(root)` — один раз на всю
  страницу; `vis_overrun = comparison.vis_overrun_by_slug(slugs, passports, vis_rows)`.
- Всё передаётся в `investor_summary.build_table(...)`, результат — в
  шаблон.

Ни один объект не пропадает из списка из-за отсутствия одной из трёх
цифр — читаем как есть, недостающее показываем прочерком (см. «Чего
может не быть»).

## Экран

Новый пункт в сайдбаре, рядом с «Прогнозируемое удорожание»: заголовок
«Инвесторам», ссылка на `/investors`.

Страница — `page-head` с заголовком «Инвесторам» и коротким пояснением,
ниже — одна карточка `sections-card` с таблицей:

| Объект | Смета | Прогнозируемое удорожание | Подписанное удорожание | Дельта |
|---|---|---|---|---|

Без панели поправок на НДС/инфляцию — сырые цифры, как есть, чтобы
отчёт отвечал на один прямой вопрос, а не воспроизводил всю логику
страницы сравнения. Без выгрузки в PDF на первом шаге.

Заголовки таблицы кликабельны — переиспользуется существующий скрипт
сортировки `.sections-table` (та же копия, что уже есть в
`compare.html` и `compare_vs_average.html`; в этом шаблоне — своя
копия, по тому же принципу).

Дельта в ячейке — числом, с классом `is-worse`, когда она положительна
(риск ещё не закрыт), и `is-better`, когда отрицательна или равна
нулю — те же классы, что уже красят цифры на странице сравнения.

### Чего может не быть

- **Ни одного объекта в системе** — карточка с пустым состоянием
  (`empty-state`), как на других страницах с пустым списком.
- **Смета не загружена** — «—» в колонке «Смета», объект остаётся в
  списке.
- **Файл удорожания не загружен, не разобрался, или его дельта не
  привязана к смете** — «—» в «Подписанное удорожание».
- **Реестр ВИС не загружен, или объект не сопоставился ни с одной
  строкой** — «—» в «Прогнозируемое удорожание».
- **Не хватает одной из двух цифр для дельты** — «—» в «Дельта», не
  ноль.

## Что не делается

- НДС / инфляция — не этот отчёт.
- Выгрузка в PDF/Excel — можно добавить отдельным шагом, если
  понадобится после того, как посмотрят на страницу.
- Отдельный доступ для внешних инвесторов — не нужен по решению
  пользователя.
- Разбивка дельты по видам работ — только итоговые цифры по объекту в
  этой сводке; для разбивки по видам работ уже есть карточка
  «Удорожание объекта» на странице самого проекта.

## Тесты

- `app/investor_summary.py`: смета/прогноз/подписанное считаются
  верно по каждой из трёх цифр в отдельности; дельта считается только
  когда обе величины известны и не искажается, когда одна из них
  отсутствует; `from_estimate=False` в отчёте удорожания даёт
  прочерк, а не дельту против «было»; сортировка по названию; итоговая
  строка суммирует только известные значения и считает их количество;
  пустой список объектов.
- Маршрут `/investors`: страница отвечает 200, объект без сметы /
  файла удорожания / совпадения в реестре не роняет страницу и не
  выпадает из списка, пункт сайдбара ведёт на страницу.
