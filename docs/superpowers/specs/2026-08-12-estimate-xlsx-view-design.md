# Просмотр сметы (.xlsx) в проекте

## Цель

При создании проекта дать возможность приложить смету в формате `.xlsx` и
затем открывать её прямо в браузере как таблицу — без скачивания и без
Excel на компьютере.

## Хранение

Смета — третий, необязательный файл при создании проекта (рядом с ДГП и
ТЗ). Если файл загружен, сохраняется как `raw/smeta.xlsx` — по аналогии с
`raw/dgp.docx` и `raw/tz.docx` (`app/storage.py`, `app/routes.py:create_project`).
Если файл не загружен, проект создаётся как сейчас, без сметы.

Признак «у проекта есть смета» — просто существование файла
`raw/smeta.xlsx` на диске. Отдельное поле в `passport.json` не нужно.

## Маршрут просмотра

Новый маршрут `GET /projects/<slug>/smeta`:
- 404, если `raw/smeta.xlsx` не существует (или слаг не существует).
- Иначе рендерит страницу с таблицей(ами) из файла.

На странице проекта (`project.html`) — кнопка/ссылка «Смета» рядом с
названием проекта, показывается только если файл есть.

## Рендеринг

Новый модуль `app/estimate.py`. Библиотека — `openpyxl` (добавить в
`requirements.txt`).

Файл открывается двумя проходами:
- `data_only=True` — чтобы получить посчитанные значения формул (а не
  текст формулы);
- обычный режим — чтобы взять оформление: цвет заливки ячейки,
  жирный/курсив, границы, объединённые ячейки (`merged_cells.ranges`),
  ширина столбцов, горизонтальное выравнивание.

Каждый лист книги, кроме скрытых (`sheet_state != "visible"`),
рендерится в отдельную HTML-таблицу. Если листов больше одного —
вкладки сверху страницы (просто ссылки/кнопки, переключающие видимую
таблицу; JS без перезагрузки страницы).

Числа выводятся в вычисленном виде (значение, не формула). Формат
отображения числа (разделители, число знаков после запятой) — по
возможности через `number_format` ячейки; в остальном — как есть.

### Явно не поддерживается (сообщить пользователю не нужно — просто
не отображается)

- Встроенные картинки, логотипы, диаграммы внутри книги.
- Сложное/градиентное/условное форматирование.
- Точные шрифты — используется единый читаемый шрифт таблицы приложения;
  из оформления переносятся только: жирный, курсив, цвет фона ячейки,
  горизонтальное выравнивание, наличие границ, объединение ячеек,
  относительная ширина столбцов.

## Загрузка и ошибки

`new_project.html`: третье поле загрузки файла, такое же по виду, как у
ДГП/ТЗ (`file-drop`), с `accept=".xlsx"`, без звёздочки/отметки
обязательности.

`create_project` (`app/routes.py`):
- Если файл сметы не приложен — пропускаем, ничего не сохраняем.
- Если приложен, но расширение не `.xlsx` — ошибка на форме:
  "Смета должна быть в формате .xlsx" (по аналогии с проверкой ДГП/ТЗ).
- Если расширение верное, но `openpyxl` не может открыть файл
  (испорченный/не Excel файл) — ошибка на форме: "Не удалось прочитать
  смету — убедитесь, что это корректный файл .xlsx". Проверка идёт до
  создания папки проекта, поэтому при такой ошибке проект не создаётся —
  так же, как сейчас ведут себя ошибки чтения ДГП/ТЗ.

## Тесты

- `app/estimate.py`: юнит-тесты на рендеринг — простой лист с числами,
  лист с объединёнными ячейками, несколько листов, скрытый лист
  игнорируется, формула рендерится как посчитанное значение.
- `app/routes.py`: тест создания проекта с корректной сметой (файл
  сохранён, маршрут `/smeta` отдаёт 200 и содержит данные из файла);
  тест создания без сметы (маршрут `/smeta` — 404); тест с испорченным
  файлом сметы (форма возвращает ошибку, проект не создан).

## Вне рамок задачи

- Повторная загрузка/замена сметы после создания проекta — не запрошено,
  не делаем.
- Извлечение данных из сметы в паспорт объекта — не запрошено.
- Поддержка старого формата `.xls` — явно отклонено пользователем.
