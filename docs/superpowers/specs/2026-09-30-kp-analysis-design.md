# Анализ КП — сопоставление предложений подрядчиков со средней по классу

## Зачем

Тендерная сводная таблица приходит с ценами 5–10 подрядчиков. Специалист
вручную отмечает в колонке «Комментарии (ЗАМЕЧАНИЯ МРГ)» каждого блока, где
раздел завышен, где подрядчик не расценил подраздел и где стоимость СМР
необоснована. Программа должна делать эту разметку сама, опираясь на
средние ₽/м² по уже загруженным объектам того же класса.

## Что делает пользователь

На странице «Анализ КП»: загружает .xlsx (сводная тендерная таблица),
выбирает класс жилья (`passport.BUILDING_CLASS_OPTIONS`), вводит общую
площадь объекта в м². Получает таблицу на странице и кнопку «Скачать
отработанный файл».

## Разбор файла (`app/kp_analysis.py`, `parse_offer`)

Лист — первый. Структура (по образцу «исходник.xlsx»):

- **Строка подзаголовков** — первая строка, где встречается ячейка
  «Комментарии». Каждая такая колонка — конец блока подрядчика. Блок —
  колонки между предыдущей «Комментарии»/«Ожидаемая стоимость» и этой.
- В блоке: колонка с заголовком, начинающимся на «Стоимость всего» (но не
  «за объемы заказчика») — это «Материалы»; следующие по строке ниже —
  «СМР», «Косвенные расходы», «Всего» (ищутся по подписям строки ниже, не
  по смещению). «Ожидаемая стоимость» — колонка сразу после «Комментарии»
  с таким заголовком.
- Имя подрядчика — непустая ячейка в пределах блока в строке, где в
  шапке стоит «Наименование контрагента»; нет такой строки — «Подрядчик N».
- **Строки** ниже шапки: колонка «№ раздела» (B). Раздел — номер без точки
  внутри (`^\d+\.?$`), подраздел — номер с точкой внутри (`10.1`, `10.1.1`),
  позиция — пусто. Строка «Лот …» (итог по лоту) пропускается. Название
  раздела — «Статья СМР», если пусто — «Наименование работ».
- Вид работ раздела — `estimate_sections.classify(название)`.
- Значения — кэшированные результаты формул (`data_only=True`). Формула без
  кэша в нужной ячейке → понятная ошибка «откройте файл в Excel и
  сохраните».

## Средняя по классу (`class_averages`)

Для каждого загруженного объекта выбранного класса, у которого есть смета
и площадь, по каждому виду работ:
`стоимость = смета + подписанное удорожание (current из отчёта удорожания,
если он мерен от сметы) + прогнозируемое удорожание`. Источники и запасные
варианты — те же функции, что у «Сводки по удорожанию»
(`_estimate_totals`, `_cost_increase_report`, `_predicted_increase_report`).
Каждая стоимость приводится к НДС 22% (`comparison.project_factor`,
`Adjustments(vat_rate=22)`); объект с неизвестной ставкой НДС выпадает и
показывается списком. Средняя ₽/м² — портфельная: Σ стоимости / Σ площадей
тех объектов, где этот вид работ есть (как `_average_work_rows`).

## Анализ (`analyze`)

- Раздел, где ни у одного подрядчика нет суммы > 0, — вне тендера:
  пропускается целиком.
- Предложение ₽/м² = сумма «Всего» подрядчика по разделу / площадь.
- Ожидаемая стоимость = средняя ₽/м² × площадь → в «Ожидаемая стоимость»
  на строке раздела.
- Отклонение = предложение / ожидаемая − 1:
  - > 30% → «Существенно завышена стоимость за раздел»;
  - > 0% → «Завышена стоимость за раздел»;
  - иначе ничего («занижена» не пишем).
- Сумма раздела у подрядчика 0/пусто → «расценить раздел.».
- Подразделы: сумма 0/пусто → «расценить подраздел.»; иначе СМР > 50%
  материалов (или материалов 0 при СМР > 0) → «необоснована стоимость СМР».
- Нет средней по виду работ (нет объектов класса с таким разделом или
  раздел не распознан) → без оценки раздела, на странице «нет данных».
  Замечания подразделов при этом всё равно ставятся.

## Запись файла (`write_remarks`)

Исходный файл открывается заново с формулами, в нужные ячейки пишется
текст/число; ячейка, где уже есть значение, не перезаписывается. Книга
помечается на пересчёт при открытии (`fullCalcOnLoad`), потому что openpyxl
не сохраняет кэш формул. Результат кладётся во временную папку
`<PROJECTS_ROOT>/../kp_analysis/<token>.xlsx` (вне папки проектов), файлы
старше суток удаляются при каждом новом анализе. Скачивание —
`GET /kp-analysis/download/<token>`.

## Страница

Форма (файл, класс, площадь) + результат: таблица «раздел × подрядчик»
(₽/м² и отклонение, завышенные подсвечены), колонка средней по классу,
число объектов в выборке, выпавшие объекты, кнопка скачивания. Ошибки
ввода — сообщение над формой, как на странице импорта.

## Не делаем

Оценку «завышено оборудование / просим КП на оборудование» — это суждение
по позиции, в базе нет цен по позициям. Привязку КП к объекту и хранение.

## Проверка

Тесты модуля на маленькой книге той же формы; тесты маршрутов (форма,
ошибки ввода, успешный анализ, скачивание). Ручной прогон на
«исходник.xlsx» со сверкой с разметкой раздела 10 из «отработанный фаил.xlsx».
